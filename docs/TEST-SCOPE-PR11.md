# XPL-EX-NEXT 1.6.6 TEST-SCOPE2

Тест PR #11: https://github.com/Mobilelegends74/XPL-EX/pull/11
Исходный PR-коммит: 2a2e155044819a938fe66db0b9930233167ee899.
Доработки TEST-SCOPE2: явное удаление всех назначений общим переключателем,
защита от восстановления назначений запоздалыми отчётами работающих хуков,
проверка фактического удаления из scope, сверка состояния при возврате в XPL-EX
и освобождение зависшего запроса через 45 секунд без автоматического повтора.
Диагностика количества назначений, scope и callback теперь попадает в экспорт
LSPosed через защищённый командный мост (тег XLua.Scope).
Основа: релиз 1.6.6. Package eu.faircode.xlua, versionCode 172 и протокол
моста 1.5.5 сохранены. APK подписывается постоянным релизным ключом, сертификат
проверяется Actions. Стабильный релиз и его APK не заменяются.

## Перед тестом

1. Экспортируйте настройки XPL-EX и сохраните стабильный APK 1.6.6 для отката.
2. Установите тестовый APK поверх текущего, не удаляя приложение и его данные.
3. Перезагрузите телефон для обновления загруженного в system_server кода.
4. В LSPosed оставьте модуль включённым и сохраните System Framework в области
   действия. Для проверки используйте одно некритичное приложение в основном
   Android-профиле, например DevCheck, без заранее назначенных хуков.

## Основные проверки

- Уберите только тестовое приложение из области действия XPL-EX в LSPosed.
  Назначьте ему хуки внутри XPL-EX. Если LSPosed запросит подтверждение,
  разрешите. Приложение должно появиться в области действия без ручной галочки.
- Перезапустите тестовое приложение (принудительная остановка и новый запуск).
  При необходимости перезагрузитесь, если LSPosed просит это сделать. Проверьте
  реальную работу одного выбранного хука, а не только состояние переключателя.
- При наличии двух назначенных хуков отключите один: приложение должно остаться
  в области действия. Отключите последний: оно должно удалиться из области.
- Снова включите хуки: добавление должно работать повторно, без зависания UI
  и многократных одинаковых запросов. Проверьте также назначение через профиль
  подмены устройства, если вы им пользуетесь.
- Если LSPosed предлагает отклонение запроса, отклоните один: настройки хуков
  должны сохраниться, без ложного сообщения об успешном включении в LSPosed.
  Новая операция назначения должна позволять повторно запросить добавление.
- При включённых хуках снимите галочку только у DevCheck в LSPosed. Вернитесь
  в XPL-EX: ручной выбор не должен незаметно отменяться. Выключите и снова включите
  общий переключатель XPL-EX: новый явный выбор должен снова запросить scope.
- Оставьте DevCheck работающим и выключите все его хуки. Даже если старый процесс
  ещё присылает отчёты, назначения не должны восстанавливаться. Для фактической
  выгрузки уже установленных хуков принудительно остановите DevCheck.
- Повторите цикл включить/подтвердить/выключить три раза. Если запрос остался без
  ответа, после 45 секунд новая явная операция должна позволять повторить его.

Не отключайте System Framework: он нужен для моста настроек и БД. Назначения
другого Android-профиля из основного профиля намеренно не синхронизируются.
Наличие области действия не доказывает работу каждого хука.

## Что прислать при проблеме

Шаги и время воспроизведения, версия LSPosed, имя пакета и Android-профиль,
экспорт журнала LSPosed и Android Logcat. Служебный тег новой функции — XLua.Scope.
Особенно полезны случаи: хуки сохранились, но scope не добавился; последний хук
отключён, а scope остался; System Framework исчез; запросы дублируются или UI завис.

## Откат

Установите стабильную 1.6.6 поверх тестовой и перезагрузитесь. Одинаковый
versionCode 172 и сертификат сохраняют возможность замены без очистки данных.
Область действия LSPosed при необходимости восстановите вручную.
