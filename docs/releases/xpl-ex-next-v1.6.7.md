# XPL-EX-NEXT v1.6.7

## Изменения

- Добавлена динамическая область действия LSPosed: после успешного назначения хуков XPL-EX запрашивает добавление выбранного приложения. LSPosed может потребовать подтверждение.
- После удаления последнего назначения приложение удаляется из области действия. Если другие хуки остаются, область действия сохраняется.
- System Framework остаётся включённым для работы моста настроек и базы данных.
- Запросы ожидают подключения сервиса, не дублируются для уже добавленных приложений и обрабатывают позднее подтверждение после отключения хуков.
- Ошибка запроса области действия не отменяет сохранённые назначения хуков.

Реализация [HankAviator](https://github.com/HankAviator), [PR #11](https://github.com/Mobilelegends74/XPL-EX/pull/11). В релиз включён исходный код автора, проверенный на OnePlus 13R с LSPosed 2.2.1; экспериментальные доработки TEST-SCOPE2 не включены.

## Установка и ограничения

- Версия **1.6.7**, versionCode **173**. Пакет `eu.faircode.xlua`, API 101, bridge-протокол **1.5.5** и постоянная подпись сохранены.
- Устанавливайте поверх предыдущей версии без удаления данных. После обновления перезагрузите устройство.
- Если запрос добавления не появляется и LSPosed сообщает `Blocked by user`, удерживайте XPL-EX в списке модулей LSPosed и выберите **Reset scope request setting**, затем повторите назначение хуков.
- Запросы относятся к текущему Android-профилю. Другие профили настраивайте из их экземпляра XPL-EX или вручную в LSPosed.
- Изменение scope не выгружает уже установленные хуки из работающего процесса: перезапустите целевое приложение.
